# Final AI Instruction

Back to [[Master Game Planning Document]] | Previous: [[10 Scope Monetization Risks and Limitations]]

Before development begins, AI must read this entire document.

**AI must identify:**
1. Missing critical information.
2. Contradictory requirements.
3. Unrealistic expectations.
4. Major technical risks.
5. Major design risks.
6. Systems that depend on other unfinished systems.
7. Areas requiring prototypes or research.
8. Areas where additional detail would materially improve the roadmap, and offer to help expand them.
9. If critical success requirements are missing, AI must identify them and help the user define them before dependent development begins.

**AI will then produce:**
- A concise understanding of the game.
- The game's primary gameplay loop.
- The major system architecture.
- A dependency-aware development roadmap.
- An MVP definition.
- Development phases.
- A checklist for each phase.
- Known risks and concerns.
- Testing requirements.
- Clear completion criteria.
- A consolidated understanding of the information the user provided so the user can verify that AI understood the game correctly.

## During development

| Source | Defines |
|---|---|
| THE MASTER GAME PLANNING DOCUMENT | WHAT the game should become |
| THE ROADMAP | WHEN major parts should be created |
| FEATURE SPECIFICATIONS | HOW individual systems should behave |
| THE CODE / ROBLOX PROJECT | WHAT CURRENTLY EXISTS |

AI must not confuse these four sources of truth.
If implementation and documentation begin to disagree, AI must identify the conflict rather than silently choosing one.

The goal is NOT to generate the most code possible.
The goal is to create the intended game correctly, incrementally, safely, and without unnecessary complexity.
